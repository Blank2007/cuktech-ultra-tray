## 一、我理解的需求

| 项 | 内容 |
|---|---|
| 设备 | 酷态科 CUKTECH 10 号 Ultra（CUKTECH 10 GaN Charger Ultra，疑似型号 AD1204U，120W 带屏充电器），带蓝牙，已加入米家 App，可看功率、做控制 |

## 二、GitHub 上找到了什么（这是最重要的发现）

### 1) 直接对口、可直接抄的 —— `kairui1108/cuktech-ble-ha`
<https://github.com/kairui1108/cuktech-ble-ha>（MIT）
「CUKTECH 10 GaN Charger Ultra 接入 Home Assistant」，包含三部分：
- **Python BLE Server**（`ble_server/`，bleak + cryptography）：直连充电器，实时功率、端口控制、协议开关、倒计时；带 Web UI / MQTT / HA 集成。
- **ESP32 固件**（`esp32_ble/`）：独立硬件桥，C 实现，带 `miot_auth.h`（HKDF + HMAC + AES-CCM）与 `ble_manager.c`。
- **完整协议逆向结论**：GATT 句柄、认证握手、AES-CCM 参数、MiOT TLV、PIID 语义、功率字节布局、重连/退避策略。

→ **这就是我们的"规格书 + 参考实现"**，我已下载到 `research/cuktech-ble-ha/`（238 个文件）与 `research/cuktech-ble-esp32/`（78 个文件）。

### 2) 配套工具
- `PiotrMachowski/Xiaomi-cloud-tokens-extractor` —— 登录小米账号批量导出设备 **token**（协议认证必需）。
- `kairui1108/cuktech-ble-esp32` —— 上面的 ESP32 独立固件版（如果你不想让 PC 一直占着蓝牙连接，这条路更稳）。

### 3) 参考但也容易误导的
- `wqytommy666/cuktech-screen-controller` —— 酷态科 **AP01**（10 号电能基站，320×240 屏）的刷机/控屏工具。
  ⚠️ **AP01 ≠ 10 号 Ultra**，它走 Wi-Fi + 固件刷写，协议完全不同，**不要混用**。
- `home-assistant/core` 的 `xiaomi_ble`（底层 `xiaomi-ble` 库）—— 只处理**被动广播**（温湿度传感器那类），本充电器不走这条路，读不到功率。
- `rytilahti/python-miio` —— 米家 **Wi-Fi** 设备的主力库；对 BLE 只有零散支持，参考价值有限。

### 4) 结论
**不用从零逆向**。协议已有 Python + C 两份可交叉验证的实现，我们要做的是"移植 + 做成托盘产品"。

## 三、协议结论（能不能做？能）

- **协议类型**：小米 **MIoT BLE（mible）**，服务 `0xFE95`，私有特征，**AES-CCM 加密会话**，必须先认证。
  → **不是**明文 GATT，也**不是**被动广播。
- **认证**：设备初始化(0xA4) → 密钥交换 → `CMD_LOGIN(0x24)` → 双向随机数 →
  `HKDF-SHA256(salt = app_random||dev_random, info="mible-login-info", L=64).derive(TOKEN)`
  → `dev_key/app_key/dev_iv/app_iv` → 互验 HMAC-SHA256 → 收到 `0x21` 即成功。
  **需要设备的 12 字节 token**（一次性配置，之后缓存在本地）。
- **数据**：SIID=2，**PIID 1/2/3/4 = C1/C2/C3/A 四个口**，每个值 4 字节：
  `[状态][code][电流×0.1A][电压×0.1V]`，**功率 = 电压 × 电流**（设备不直接给功率）。
  → 分辨率 0.1V / 0.1A，与米家 App 同源，**精度天花板就在这**（例：20.1V × 2.5A = 50.2W）。
- **实时性**：C1/C2 由固件**主动推送**；**C3/A 不推送，只能 3 秒轮询一次**。
- **协议类型**（PD/PPS/QC/UFCS/SCP）：权威来源是 **PIID 17/18** 的位域，不是口数据里的 `code` 字节。
- **控制**：端口开关 = PIID 16 位掩码（bit0..3），必须"先读后改再写"；场景模式 PIID 5、协议开关 PIID 21、倒计时 PIID 9-12、息屏 PIID 6、语言 PIID 13。

## 四、技术选型建议

| 方案 | 体积 | 常驻内存 | 开发成本 | 结论 |
|---|---|---|---|---|
| **C# .NET 8 + WinForms NotifyIcon + WinRT BLE** | self-contained 单文件 **≈52MB**；框架依赖版 ≈1MB | 40-70MB | 低（最快跑通） | **推荐主方案** |
| **Rust + btleplug（或 windows-rs）+ tray-icon** | **5-10MB** | 15-25MB | 1.5-2 倍 | 体积/内存最优，二期可评估 |
| C++ Win32 托盘 + WinRT + Native AOT | 7-15MB | 20-40MB | 高 | 极致瘦身才考虑 |
| Python + bleak + pystray | 15-40MB | 60-120MB | 最低 | 只做原型 |
| WinUI3 / Tauri / WPF / Go / AHK | — | — | — | 排除（重 或 BLE 能力缺口） |

**建议**：先用 C# 把协议和交互跑通（一天能出可用的探针），确认稳定后再决定要不要为体积移植 Rust。
两者在 Windows 上最终都调 WinRT，**协议解析层是纯字节逻辑，可以 1:1 翻译**，不存在返工。

为什么不是 10MB：WinForms/WPF 目前**官方不支持裁剪**（`dotnet/winforms#4649`、`dotnet/wpf#3811` 仍未修），
self-contained 必须整包带运行时。真在乎体积就走 Rust。

## 五、产品形态设计（草案，待你确认）

```
托盘图标（可显示 5W/65W/120W 数字）
  ├─ 左键单击 → 弹出小面板（200×320，靠托盘，无任务栏图标）
  │    ├─ 顶部：总功率大数字 + 迷你曲线（最近 60s）
  │    ├─ 四行口卡片：C1 / C2 / C3 / A
  │    │     每行：电压 · 电流 · 功率 · 协议(PD/PPS/UFCS...) · 开关
  │    └─ 底部：连接状态 / 场景模式 / 倒计时 / ⚙设置
  └─ 右键 → 菜单：连接|断开 · 开机自启 · 复制设备信息 · 日志 · 退出
```

- **连接策略**：默认"**后台保持连接**"（点开就是实时值，不用等握手 1-2 秒）；
  设置里可切"**仅面板打开时连接**"（更省电、更少和手机抢连接）。
- **精度与刷新**：C1/C2 靠推送（亚秒级），C3/A 靠 3 秒轮询；面板刷新 500ms 足够。
- **托盘图标动态数字**：用 GDI 画位图转 Icon，零依赖。

## 六、风险清单（这些决定项目成败）

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 1 | **Windows 上没人验证过**（作者只在 Linux/ESP32 跑通） | 可能卡在 MTU/分片/通知顺序 | **M0 真机探针优先**，1-2 天见分晓 |
| 2 | **token 获取**需要小米账号登录（扫码/密码） | 首次配置门槛 | 内置扫码登录（复用 `xiaomi_cloud.py` 思路）；退路：让用户用 token-extractor 跑一次粘贴 |
| 3 | 认证状态机可能"卡死"（作者遇到需重启进程） | 偶发连不上 | 断连重试 + 退避 + 提示用户拔插一次电源；程序自愈（外部拉起） |
| 4 | 帧长 240 字节，**MTU 23 时会被分片** | 解密全部错位 | 请求 `GattSession.MaxPduSizeRequested=247`，实测协商值并打印 |
| 5 | 固件版本差异（参考实现验证于 `2.1.2_0073`） | 布局可能不同 | 先读固件版本；异常时回落"只读+告警" |
| 6 | **米家 App 抢占连接**（BLE 同时只能一个中心） | 打开米家时我们连不上 | 面板显式提示；或改成"面板打开才连" |
| 7 | 写操作是"读-改-写"，GET 失败按 0 兜底会**误关其它口** | 断充 | 取不到基线就拒绝写入（参考实现已有血泪注释） |
| 8 | 蓝牙适配器要求 BLE 4.0+ | 少数老机器不可用 | 启动时检测并提示 |

法务：仅本地读取/控制自己的设备，不刷固件、不破解加密内容，风险等同手机 App，**不涉及保修问题**。

## 八、需要你确认的问题

1. **设备确认**：是不是这颗「120W 带屏、支持米家的 10 号 GaN 充电器 Ultra」？米家 App 里显示的名字/型号是什么？固件版本能看到吗？
2. **米家账号**：愿意让工具用你的小米账号**扫码登录一次**换取 token 吗？（仅本地保存，不上传）如果介意，就先手动用开源工具导一次 token 粘进来。
3. **功能范围**：只要"看功率"（最省事、最稳），还是要"能控制"（开关口/模式/倒计时）？
4. **占用优先还是稳定优先**：能接受 52MB 单文件 / 40-70MB 内存的 C# 版吗？还是宁可多等几天要 5-10MB 的 Rust 版？
5. **日常习惯**：手机米家 App 平时会一直开着吗？（会抢蓝牙连接）
6. 电脑是 Win10 还是 Win11？蓝牙适配器型号/是否主板自带？
